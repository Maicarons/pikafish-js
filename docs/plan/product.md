# 产品设计

> 关联：[方案总览](/plan/overview) · [选型记录](/plan/decisions) · [系统架构](/plan/architecture) · [路线图](/plan/roadmap)

## 1. 产品定位

`pikafish-js` 首先是一个**开发者工具**，其次才是一个演示产品。演示站的任务不是做成商业对弈平台，而是证明三件事：

1. 引擎在真实浏览器里稳定、够强；
2. 普通用户不需要理解 UCI、WASM、NNUE 也能下完一局；
3. 开发者能照着演示站的代码，在自己的产品里复现。

因此产品设计遵循四条原则：

- **默认简单，进阶可见**：打开就能下；分析、PV、NPS 等信息收进可展开面板。
- **极简界面**：只保留棋盘、落子、难度、棋谱与必要提示；不做拟物贴图、复杂动效和装饰性面板。
- **诚实**：明确告知首次加载体积、单线程/无 SIMD 降级、引擎强度与规则限制，不伪装成“云端 AI”。
- **不打扰**：无账号、无广告、无追踪、无强制联网。

### 1.1 自研 UI 的边界

- 棋盘与棋子用 SVG + CSS 变量实现，不引入 `chessgroundx` / `xiangqiground` 作为运行时依赖。
- 交互可参考现有开源项目（点击/拖拽、合法点、最后一着、键盘导航），但代码按本项目结构重写。
- 棋子与图标优先使用原创或可记录来源的素材；若复用第三方素材，在 `NOTICE` 与“关于”页记录来源。
- UI 只依赖 `@pikafish-js/rules` 与核心包公共 API，不直接解析 UCI 或引擎内部状态。

## 2. 信息架构

```text
/                     首页：一句话介绍 + 开始下棋 + 加载状态
/play                 人机对弈
/analysis             局面分析（FEN / 棋谱导入，v0.1 支持 FEN）
/settings             引擎与界面设置（线程、Hash、动画、声音）
/about                项目说明、许可证、上游致谢
```

v0.1 只做单页应用内的视图切换，不做多页路由；所有状态保存在内存与 `localStorage`（设置项），不上传。

## 4. 核心流程

```text
进入页面
  → 检查缓存/能力
  → 显示“加载引擎”进度（wasm → 网络 → 初始化）
  → 选择先手/后手 + 难度（可跳过，用默认）
  → 对局
      → 人走子 → 规则校验 → 动画 → 轮到引擎
      → 引擎搜索（可取消/悔棋）→ 落子 → 更新棋谱
      → 终局判定 → 结果弹层 → 再来一局 / 复盘
  → 离开页面 → dispose
```

### 4.1 加载体验

| 阶段 | 文案 | 进度来源 |
| --- | --- | --- |
| 引擎代码 | 正在加载引擎… | wasm 下载/编译 |
| 网络权重 | 首次需下载约 50 MB 棋力网络 | 流式读取 |
| 初始化 | 正在唤醒引擎… | `uci` / `isready` |
| 就绪 | 可以开始对局 | 收到 `ready` |

- 首次加载显示“约 50 MB，之后会缓存”，避免用户误以为卡死。
- 若应用已通过 `netData` 打包网络，跳过下载阶段，显示“正在加载内置网络…”。
- 缓存命中时跳过网络进度，直接显示“正在唤醒引擎…”。
- 失败时给出具体原因与“重试 / 清除缓存 / 降低线程数”按钮。

### 4.2 对局状态

```text
idle → loading → ready → humanTurn → engineThinking → engineMove → humanTurn
                                   ↘ gameOver（将死/困毙/和棋/认输/超时）
```

- 引擎思考时禁止人走子；但允许“悔棋/认输/新局”，这些操作先 `stop`。
- 页面隐藏时若引擎仍在思考，继续完成当前一步（避免回来后局面错乱）；若在分析模式，暂停无限搜索。

## 5. 难度设计

### 5.1 约束

Pikafish 的 UCI 选项里**没有** Stockfish 的 `Skill Level`。不能通过一个选项直接调弱。可用手段只有：

- 限制搜索深度/时间；
- 用 `MultiPV` 拿到多个候选，按评估差与随机性选择较弱着法；
- 限制线程（对棋力影响有限，主要影响等待时间）。

因此难度是**产品层策略**，不是引擎开关。

### 5.2 七档设计（v0.1 实现）

| 档位 | 名称 | 搜索预算 | 选着策略 | 目标体验 |
| --- | --- | --- | --- | --- |
| L1 | 入门 · 随机走子 | 100 ms | 从全部合法着法中均匀随机 | 会送子，初学者可赢 |
| L2 | 轻松 · 1 层 | `depth 1` / 180 ms | 最佳着法 | 会吃送到嘴边的子，仍常漏杀 |
| L3 | 业余 · 3 层 | `depth 3` / 350 ms | 最佳着法 | 有基本战术意识 |
| L4 | 进阶 · 5 层 | `depth 5` / 700 ms | 最佳着法 | 需要认真下 |
| L5 | 高手 · 8 层 | `depth 8` / 1.4 s | 最佳着法 | 稳定压制休闲玩家 |
| L6 | 大师 · 12 层 | `depth 12` / 2.6 s | 最佳着法 | 多数业余玩家难以取胜 |
| L7 | 特级大师 · 16 层 | `depth 16` / 5 s | 最佳着法 | 接近引擎真实棋力 |

实现细节：

- `depth` 与 `movetime` 是**双上限**，谁先到就停，避免低端设备上一档要等十几秒。
- L1 是唯一注入随机性的档位；随机源可注入，便于测试复现。
- 低档位仍使用 NNUE，不切换到“规则 AI”；走法风格一致，只是搜得浅。
- 档位表集中在 `apps/demo/src/main.ts` 的 `LEVELS`，改数值即可调整。

**与初版草案的差异**：草案让 L1–L3 用 MultiPV 按概率选次优着法。实测发现浅层搜索本身已经足够弱，
再叠加“随机次优”会让失误显得不可解释——玩家分不清是引擎弱还是程序坏了。v0.1 因此简化为
“只调搜索预算 + 仅 L1 随机”，档位差异单调、可解释。代价是低档位偶尔会走出连贯的好棋。

### 5.3 校准（v0.2）

M4 结束后用固定开局跑一次**档位循环赛**（每对 20 局，单线程、固定 Hash），确认：

- 相邻档位胜率单调；
- L1 不会弱到“随机送将”；
- L7 与 L6 有可感知差距。

**v0.1 未执行**：档位表是按设计给出的，没有胜率数据支撑。这项校准随 v0.2 的难度调整一起做，
届时把结果补进本节与[基准数据](/guide/benchmarks)。

绝对 Elo 不在 v0.1 承诺范围内；文档只描述“目标体验”，不标注虚假等级分。

## 6. 计时系统

### 6.1 模式

| 模式 | 规则 | 默认 |
| --- | --- | --- |
| 包干 | 每方总时长，用完判负 | 10 分钟 |
| 加秒 | 每步走完加固定秒数 | 5 分 + 3 秒 |
| 不限时 | 只用于分析/教学 | 关闭计时 |

- 人类时钟在落子后切换；引擎时钟从收到 `position` 开始计时，到 `bestmove` 结束。
- 引擎时间预算 = 剩余时间 / 预估步数 + 加秒 − `Move Overhead`（默认 10 ms，网络/主线程繁忙时可调高）。
- 超时判定由 UI 负责；引擎不感知时钟。

### 6.2 边界

- 页面隐藏/切后台：人类时钟继续走（与真实比赛一致），并在恢复时提示。
- 悔棋不返还时间（避免利用悔棋拖时间）；可在设置中改为“练习模式返还”。
- 引擎思考超时（无响应）→ 判引擎卡死，提示重试，不直接判负。

## 7. 交互细节

### 7.1 走子

- 点击选中 → 显示合法落点（圆点）与可吃子（圆环）→ 再点落子。
- 支持拖拽；拖拽到非法位置回弹。
- 最后一着高亮起点/终点；被将军时帅/将位置闪烁一次（尊重 `prefers-reduced-motion`）。
- 动画 120–160 ms；可在设置中关闭。
- 音效默认关闭；开启后只使用短促的落子/吃子/将军提示。

### 7.2 悔棋

- 人机模式默认一次悔两步（引擎 + 人类），回到人类走子前。
- 分析模式一次悔一步。
- 引擎思考中悔棋：先 `stop`，丢弃结果，再回退。
- 悔棋后清空“当前搜索”，不复用旧 PV。

### 7.3 提示

- 点击“提示”：以 `depth 12` 分析当前局面，在棋盘上画出最佳着法箭头，并在面板显示评分。
- 提示不计入棋谱；可重复使用。
- 引擎思考中禁用提示（避免并发搜索）。

### 7.4 认输与和棋

- 认输立即结束，结果写入棋谱。
- “提议和棋”：仅当规则裁决为和（三次重复/限着/子力不足）或引擎评估连续 6 步在 ±0.50 内时可用；否则按钮置灰并提示原因。
- 引擎不会“主动求和”；避免拟人化误导。

### 7.5 新局

- 保留难度、计时、先后手设置。
- 清空棋谱、重置时钟、`ucinewgame` + `Clear Hash`。
- 若引擎正在搜索，先停止并等待 `bestmove`。

## 8. 分析模式

### 8.1 功能（v0.1）

- 输入 FEN 或从对局“进入分析”。
- MultiPV 3：显示三条主变、评分、深度。
- 评分条：cp 映射为 0–100%，mate 显示“绝杀”。
- 点击 PV 中的着法可在棋盘预览（不改变实际对局）。
- 显示 NPS、节点数、耗时、Hash 占用。
- “复制分析”导出 JSON。

### 8.2 暂不做（v0.2+）

- 全盘失误检测与“妙手/漏着”标签。
- 评估曲线与逐着对比。
- 开局库提示。
- 云端共享链接。

## 9. 棋谱

- 对局中实时生成中文记谱与 UCI 着法列表。
- “复制棋谱”输出纯文本：
  ```
  1. 炮二平五  马8进7
  2. 马二进三  车9平8
  ...
  ```
- v0.1 支持 JSON 导出（含 FEN、着法、时间、难度、结果）。
- PGN 导入导出放 v0.2；导入时必须校验合法性，拒绝非法着法。

## 10. 可访问性

- **键盘**：`Tab` 进入棋盘；方向键在 9×10 网格移动焦点；`Enter` 选子/落子；`Esc` 取消选择；`U` 悔棋；`N` 新局。
- **读屏**：每个交叉点有 `aria-label`（如“红方炮，二路，五线”）；走子后通过 `aria-live="polite"` 播报“红方炮二平五，将军”。
- **对比度**：棋子文字与棋盘底色 ≥ 4.5:1；选中/合法点不仅靠颜色区分（形状 + 颜色）。
- **动效**：尊重 `prefers-reduced-motion`；关闭动画不影响功能。
- **缩放**：200% 缩放不重叠、不截断；棋盘可横向滚动仅在极端窄屏出现。

## 11. 视觉方向

- **极简**：米白或浅灰底、细线棋盘、红黑棋子；不做木纹贴图、阴影堆叠、渐变光效。
- 字体：中文标题可用宋体/思源宋体；正文使用系统无衬线，保证可读性。
- 棋盘：9×10 网格、河界留白、九宫斜线；线条清晰，缩放不糊。
- 状态色：红方 #b91c1c，黑方 #1f2937；合法点用半透明圆，吃子用环。
- 动效：仅保留 120–160 ms 落子过渡；尊重 `prefers-reduced-motion`，可一键关闭。
- 深色模式：界面跟随系统；棋盘保持中性色，不强制反色。
- 素材：棋子/图标优先原创；第三方素材记录来源，不使用来源不明的图片。

## 12. 错误与恢复

| 场景 | 界面 | 行为 |
| --- | --- | --- |
| 网络失败 | “网络加载失败” + 重试 | 保留已下载部分？否；重新流式下载 |
| 缓存损坏 | “缓存校验失败” + 清除缓存 | 删除对应 Cache Storage 条目后重试 |
| 引擎崩溃 | “引擎需要重启” | 重建 Worker，按棋谱重放局面 |
| 内存不足 | “设备内存偏低，已降低线程数与置换表上限” | 降低 `Threads` 与 `Hash` |
| 无 SIMD | “兼容模式：搜索速度较慢” | 使用 `single-nosimd`，禁用线程设置 |
| 内置网络校验失败 | “内置网络校验失败” | 提示重新安装/更新应用，不进入对局 |
| 无合法着法 | 终局弹层 | 判定将死/困毙 |
| 页面关闭 | — | `dispose`，停止搜索 |

## 13. 文案原则

- 不显示“AI 正在思考人生”这类拟人化文案；使用“引擎思考中”。
- 不承诺“大师级”“特级大师”等等级；只描述档位与搜索设置。
- 首次加载明确写体积与缓存策略。
- 错误信息包含“发生了什么 + 用户可以做什么”，不暴露堆栈给普通用户。

## 14. 体验指标

| 指标 | 目标 |
| --- | --- |
| 首次可走子时间（网络已缓存） | ≤ 3 秒 |
| 首次可走子时间（50 Mbps 首次） | ≤ 15 秒 |
| 引擎落子等待（L4，中端笔记本） | ≤ 1.5 秒 |
| 一局完成率（演示站） | ≥ 60%（有意义的对局） |
| 非法着法/崩溃 | 0 |
| 移动端布局溢出 | 0 |

## 15. 明确不做

- 账号、排行榜、社交分享、观战。
- 内购、广告、订阅。
- 自动对弈/挂机/脚本接口。
- 任何规避平台规则的“辅助”功能。

> 产品边界越清楚，核心包越容易保持小而稳。演示站是“参考实现”，不是“商业产品”。
