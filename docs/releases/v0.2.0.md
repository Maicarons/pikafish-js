## 新增

### 蒸馏网

- `pikafish-lite.nnue`：L1=512，25,136,309 B，32 个 layer stack，特征集与教师一致
- 训练全程在 Kaggle 上跑通（自举：克隆仓库、浅取上游、校验网络、编译、造局面、
  标注、分片、训练、导出），本仓库只保留代码与结果
- 导出复核 1200/1200 局面逐位精确；同宽引擎复核 4,000 局面 worst |delta| = 0
- 棋力实测：等节点对局 300 局（4000 节点/步）比教师弱约 **158 Elo**
  （见 v1.0.0 发布说明里的完整宽度曲线）
- 训练过程、实测数据与三个否定结果（加数据已平、分档重加权是平线、改用搜索分当目标
  更弱）都写在 `training/README.md`

### 引擎包 `pikafish-js`

- `variants` / `variant`：把「用哪张网」和「用哪套 wasm」捆在一起选。权重是按特征宽度
  训练的，宽度对不上引擎会按 arch hash 拒绝，所以两者必须成对
- `engine.variant`：读回当前那一套的名字
- 不传 `variants` 时行为与 v0.1 完全一致，顶层 `builds` 与权重的用法不变

### 演示站

- 引擎面板新增「网络」选择器：强力（官方 50 MB 网）/ 精简（蒸馏 25 MB 网）
- 默认用蒸馏网：首屏少下载 25 MB，而这点棋力差距对人类玩家没有感知
- `?variant=strong|lite` 可以用链接固定选择

## 改进

- 引擎初始化后删除 WASM 文件系统里的权重副本：引擎已经把网读进内存，留着那份只是白占
  50 MB 堆（`Network::verify` 只比对路径，不重读文件，所以安全）
- `pikafish-dump` 现在会写下它真正收下的 FEN：引擎会丢掉非法局面和「轮到走方被将军」
  的局面（自对弈语料里约 7%），没有这个副产物，按局面打标的旁路数据会与特征错位
- 训练器支持第二种回归目标（教师的搜索分），分片里有 `target_internal` 就用它

## 产物

- 六套构建：两套引擎（`strong` / `lite`）× 三种能力（`threads-simd`、`single-simd`、
  `single-nosimd`），文件名 `<engine>-<build>.pikafish.js|wasm`
- `SHA256SUMS`（含两张网）、`wasm-manifest.json`、`COPYING.txt`
- 两张 NNUE 权重（`pikafish.nnue`、`pikafish-lite.nnue`）

## 附：能压到多小？

同一份语料、同一 schedule、同一对局协议（300 局、4000 节点/步）下测出来的曲线：

| L1 | 网（zstd） | Elo vs 教师 | 备注 |
| --- | --- | --- | --- |
| 1024 | 50.2 MB | 0 | 官方教师网 |
| 512 | 25.1 MB | −158 | 本版本发布的蒸馏网 |
| 256 | 12.6 MB | −220 | |
| 192 | 9.5 MB | −260 | 正好「10 MB」这一档 |
| 128 | 6.4 MB | −284 | |
| 64 | 3.2 MB | −325 | **引擎允许的最小宽度** |
| 64 但评估被清零 | 3.2 MB | −552 | 没有评估时的地板 |

每减半宽度掉 40–65 Elo（越往下越平：128→64 只掉 41）；L1=32 在引擎里编译不过
（特征变换器的分块约束），所以 3.2 MB 是现有架构下最小的可用网。KB 级做不到：32 套
layer stack 的全连接层固定占 578 KB，与宽度无关，除非改上游的评估结构。
