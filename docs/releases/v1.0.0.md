## 新增

### 四档更小的引擎

`w256`、`w192`、`w128`、`w64` 与 v0.2.0 的精简网出自同一套蒸馏流程，只改特征宽度
（上游源码里的 `constexpr IndexType L1`），语料、schedule、导出复核都一样：

- 每张网导出后复核 500 个局面逐位精确，同宽引擎再复核 4,000 个局面，worst |delta| = 0
- 棋力用 300 局固定节点对局（4000 节点/步，同一批开局）对教师网测量：

  | 引擎 | 体积 | Elo vs 教师 |
  | --- | --- | --- |
  | `strong` | 50.2 MB | 0 |
  | `lite` | 25.1 MB | −158 |
  | `w256` | 12.6 MB | −220 |
  | `w192` | 9.5 MB | −260 |
  | `w128` | 6.4 MB | −284 |
  | `w64` | 3.2 MB | −325 |

- `L1=32` 在引擎里编译不过（特征变换器的分块约束），所以 **64 是引擎允许的最小宽度**，
  3.2 MB 是现有架构下最小的可用网；KB 级需要改上游的评估结构，本项目不做

### 权重有了固定地址

- 五张蒸馏网统一放在仓库的 `networks` release，`engine.json` 只钉体积与 SHA-256
- v0.2.0 的 `pikafish-lite.nnue` 也迁到这里，权重地址不再跟着引擎版本 tag 走
- 运行时下载、Cache Storage 与哈希校验的行为不变

### 演示站

- 「引擎 → 网络」选择器列出六套：强力 / 精简 / 轻量 / 迷你 / 微型 / 极简，切换时连同
  wasm 一起换（权重只被同宽度的引擎加载）
- 默认仍是精简（25 MB）；`?variant=strong|lite|w256|w192|w128|w64` 可以用链接固定
- 选择器里显示每张网的实际字节数，弱网下可以直接选最小的那套

## 变更

- `scripts/build-wasm.sh` 按 `engine.json` 的引擎表循环，不再写死两套引擎
- CI、Release、Pages 编十八套构建（6 套引擎 × 3 种能力），任务超时 45 → 60 分钟
- 体积守卫的总量预算 7 MB → 14 MB（18 套，每套约 0.7 MB）
- `docs/guide/getting-started.md` 的产物目录结构改成实际的 `engine/<引擎>/<构建>/`
